# 水气交互：下一阶段证据

本轮已完成40组原版`UpdateLiquid(0x498B0)`直接调用采集，未将混合水气世界开放给新核心。
工具源代码在`native/reference/WaterGasReference`。这是局部函数的原版行为记录，尚非移植通过结果。

## 已观察

- 水下方是氧气或CO2且没有阻挡角落时，原版交换整格质量/元素；遇指定角落的headless事件失败时不变。
- 侧向气体让位由`DisplaceGas(0x39A00)`决定。原始指令读取`SimData+0xA0`的uint16 tick，
  以`(tick+i)&3`轮转上、左、右、下候选；不是用共享随机数挑一个方向。
- 在侧向氧气测试中，tick0将气体移到上方，tick1移到左方，tick2/3移到下方；
  随后水流入原气体格125kg，当前水格由500kg变为375kg。
- 所有主候选被阻塞的指定案例没有转移；对角候选与后续水的对角交换需要分别恢复。
- 指定的左右对角气体同时存在时，原版首先交换到右下。本地保留源/输出数据及事件次序供后续验证。

上述40个指定输入均保留原seed，不能据此概括所有混合世界都不消耗随机数。
静态分析还定位到`DisplaceLiquid(0x39C70)`和共用`DoDisplacement(0x3A1D0)`，其完整适用域待查。

## 实现前还需要完成

1. 确认tick在每次内部更新的递增、溢出和存档生命周期。
2. 还原同气体合并、属性阻塞、气体零质量与对角候选的完整判断顺序。
3. 检查气体后处理接触水、压力第二阶段遇水以及部分相变的分支。
4. 用候选模块比对全部原始网格/事件，再进行完整水气世界连续帧对照。

继续保留混合水气的明确拒绝，避免将单个水流函数的结果当成完整混合物理。
