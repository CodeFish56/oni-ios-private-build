# 水气交互与共享后处理（2026-10-16）

## 本阶段完成

核心现可在受限世界中处理Water、Oxygen、CarbonDioxide、Vacuum与稳定Unobtanium。
水气共存时，先执行热交换和两遍气体压力，再复制updated为液体阶段的固定source，
按固定source的水元素与正质量决定访问资格。所有访问累积到updated；没有按逐格变化的
updated元素重新选择扫描对象。最后在同一个升序循环中执行水气后处理，共享原版随机数顺序。

生产模块仍为11个，iOS接线仍为7个wrapper；能力为8191，完整游戏要求458752仍未满足。
当前为本机原版对照结果，没有建立ARM64或iPhone可玩性。

## 还原的控制流

| 原版入口/位置 | 已确认并实现的行为 |
| --- | --- |
| DisplaceGas 0x39A00 | 根据uint16 tick轮转上、左、右、下；目的格须同种气体或Vacuum，且无气体阻挡属性 |
| 同函数对角回退 | 上左/上右按tick奇偶轮转；只接受同种气体，并检查相应侧格可通行，不把对角真空当成同种气体 |
| DoDisplacement 0x3A1D0 | 整格气体质量与温度合并到目的，清空源格，按源、目的次序发通知；不制造flow值 |
| UpdateNeighbourLiquidMass 0x4A970 | 气体让位成功后才流入水；气体零质量/无处可去时不流入；原始重复通知顺序保留 |
| UpdateLiquid末尾 | 先右下、再左下的水气整格交换，读取updated；阻挡与可通行判断依照原版，不写flow |
| PostProcessCell 0x4DAF0 | 按访问时元素选择水或气体；水的密度检查可消费RNG，必须与气体放在同一循环 |
| 气体随机候选 | 先读温度、可能消费随机数，再排除非气体候选；不能提前跳过水格来节省随机数 |

原版气体压力的对角门槛为`(sidePhase | abovePhase) != 3`。
它既阻挡固体，也阻挡gas(1)+water(2)的组合，原表达式保留。
另一遍液体压力置换要求不同液体；当前只有Water一种，因此不触发该分支。

当最后一滴水蒸发后，含稳定内部障碍物的世界继续使用共享后处理。
新增专用连续帧验证，避免在下一帧切回旧气体API后错误拒绝同一世界。
纯水继续使用原有水后处理的正常液态温度范围，未被混合域的275..360K限制收窄。
另以273.25K和371K各5帧对照原版验证这项兼容性。

## Tick与保存

原版SimData+0xA0是uint16，构造归零。UpdateData 0x476FB在全部区域处理结束后
增加一次；零秒帧不增加，正秒帧按内部更新次数增加，空区域也增加。65535后回到0。
DisplaceGas使用增加前的tick；不以提交帧数、区域数或水格数量替代。

v15不保存tick。原版隔离进程只改tick，前后1793字节存档相同；以tick11时的存档
载入tick43210的现有SimData，接收tick保持43210。核心没有把tick加入原格式，也不在Load里清零。
当前核心仍仅支持启动时Load，缺少RNG种子的v15不能继续正时间模拟；未宣称已支持原版的运行中重载。

新增只读OniSim_GetTickCount()，返回uint32承载该uint16值。原有24字节诊断结构不变。
计数与网格、RNG、timer一起在整帧成功后提交，失败不部分前进。

## 仍然拒绝的范围

混合流体限制275..360K、水流动后质量不超过Water maxMass（1000kg）、无属性/疾病，
关闭辐射、空背墙。其他液体、反应固体、压力破坏、相变和背墙换热尚未实现。
不能据此开放完整500步世界稳定、持续游戏消息或完整游戏渲染。
采集固定一个可用CPU；多线程任务分条和跨平台所有浮点输入未证明等价。
本阶段未触发Actions、签名或安装IPA。
