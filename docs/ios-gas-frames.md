# 正时间模拟接入：受限单种气体

## 已实现

`SimCore` 现在从 `NewGameFrame` 调用已还原的压力和气体随机后处理模块。
按原版单精度调度计算更新次数及余时，保留随机种子、压力遍历方向和位移方向。
结果经原有 `PrepareGameData`、`BeginSave` C ABI 返回，增加了只读诊断状态接口。
能力从63变为127；世界稳定、完整游戏模拟、完整游戏渲染三个能力仍未开放。

本路径要求：

- 由 InitializeFromCells 提供已知种子；v15存档不含原版的随机种子，当前 Load 后不开放正时间。
- 单种 Oxygen 或 CarbonDioxide，加空真空；无内部固体、液体、疾病和位置属性。
- 气体质量必须处于已实现后处理范围（至少0.001kg）；压力后若进入未实现范围则整帧失败。
- 气体温度在300K上下0.25K以内，真空导热为0、边框有隔热状态；此范围利用原版小于1K温差不传热的分支，未实现一般热交换。
- 关闭辐射，背景墙为空，每帧最多100次内部更新。
- 每次正时间帧后必须 PrepareGameData，才能继续提交帧；不声明支持原版异步积压批次。

未实现条件明确返回 UnsupportedFeature；多提交待消费帧返回 InvalidState。
帧在临时世界、随机状态和消息队列上计算，成功后才提交，失败不留下半帧结果。

## 完整输出与原版规则

压力和随机换格产生物质通知，而非单纯网格差异。原版 ChangeSubstance 会记录
Vacuum→Vacuum；CopySimDataToGame 按格排序、去重，以前后游戏数组填写旧/新元素。
首个16×16单格氧气案例有254条通知，即使很多格仍是同一种真空。
正常气体随机候选交换通知两格；同种气体的密度温度交换分支不通知。

方向流量在帧批次开始清零，同一帧多次更新累加。水平和竖直压力交换写入四方向流量，
对角压力交换不写流量。CPU流量纹理为 `(flow.x-flow.y, flow.w-flow.z)`，乘
`1/max(finalMass,1)`；原版还比较压力后的 source 与最终 updated 元素，元素不符时比例为0。
当前受限路径 accumulatedFlow 为0，与原版指令路径和27帧实际输出一致。

这些结论来自匹配Build744825的PDB、原始DLL指令、独立原版运行与新核心执行，
不是 REA provider 的运行记录。原版文件未修改，正时间探针仅设置自身进程的CPU亲和性。

## 本机验收

| 案例 | 后续帧数 | 覆盖 |
| --- | ---: | --- |
| oxygen-single | 1 | 真空扩散、同元素通知、流量 |
| co2-two-steps | 1 | 0.4秒帧内两次更新、种子8 |
| oxygen-dense-ten | 10 | 连续帧、质量分布变化 |
| co2-dense-schedule | 5 | 0.05/0.35/0.4/0/0.2秒、余时 |
| oxygen-chunk32 | 3 | 分块maxX=32、定义世界、种子70 |
| co2-chunk33 | 3 | 分块maxX=33、种子8 |
| oxygen-pocket-three | 4 | 稀疏氧气连续推进、中间0秒帧、舍入温差 |

每帧逐字节比较18张数组、29项事件计数、四种事件记录流、保存字节；
随机种子及两个方向也与原版一致。单帧通知与流量另有独立离线复算。
质量守恒最大相对误差约6.06e-8（验收上限2e-6）。
同一批案例通过 ASan/UBSan；原11组初始化/载入回归保持通过。
辐射、混合气体、液体、位置属性、疾病、非空背墙、低质量和需热交换的输入
均明确拒绝，保存和诊断状态保持不变。

源码 `native/sim/Verify-GasFrames.py` 可复查原版记录。
摘要和原始输出哈希见 [验证记录](gas-frame-verification.json)。

## 仍未达到的目标

本轮没有混合气体位移、蒸发、液体、一般热交换、相变、疾病或建筑组件，
没有验证500步世界稳定。AOT回调、macOS ARM64编译、真机模拟及内存峰值仍待验证。
应用进入殖民地的能力检查保持关闭；本轮不触发Actions或安装新版。
